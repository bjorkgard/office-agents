# Design: Office Agents — isometric office for Claude Code agents

## Problem Statement

Local web app (`vp dev`) that shows every running Claude Code agent and subagent as a person in an isometric office. See at a glance who works, who waits, who needs you.

## What Makes This Cool

- Subagent walks in, takes a paper from the parent's desk, walks back, returns it. Paper = real prompt/result data flow.
- Agent needing input waves, speech bubble appears. Pings you across the room.
- Agent waiting on subagents takes a coffee break. Done agent walks out.
- Same project = same clothing color. Random name and gender per agent.
- Lateral idea: paper carries first line of prompt and result summary, hover to read (unverified whether anyone does this).

## Constraints

- Web, local only, Vite+ (`vp dev`), React 19 scaffold already present.
- Data feed: transcripts first (`~/.claude/projects/**/*.jsonl`), hooks later as exact-event upgrade. Both behind one normalized event interface.
- Goal: fun/side project. Weekend-sized first slice.

## Premises

1. Want own look and mechanics, not just any visualizer. Agreed (via "study first").
2. Differentiators: paper handoffs, per-project clothing color, wave+bubble. Unverified against prior art.
3. Transcripts first, hooks later (D2).
4. Web app, React, no Electron.

## Prior Art (search results only, repos not opened)

atlassian-labs/roving-office (isometric soft-3D, walk in/clock off), paulrobello/claude-office, pixel-agents-hq/pixel-agents, KbWen/agent-virtual-office, JoelHutchinson/agent-visualiser, Gaurav2693/ai-office.

## Approaches Considered

- A: Spike roving-office (+ one pixel project), then fork-or-extract + own event core. **Chosen.**
- B: Minimal 2D CSS isometric + SSE. Rejected for now: clumsy past ~12 agents. Remains the render fallback.
- C: Pixi/Three engine + adapters. Rejected for now: art pipeline delays first "whoa". Event-interface idea kept from it.

## Recommended Approach

A. One-hour spike: license, stack, sprite/state system, whether paper handoff and project colors exist. Then decide fork vs scratch. Day one regardless: normalized event interface (`agent_started`, `working`, `waiting_on_subagents`, `needs_attention`, `handoff`, `done`) with transcript adapter.

## Open Questions

- Does roving-office (or others) already do handoffs and per-project colors? License allows fork?
- Can "needs attention" and "waiting on subagents" be inferred reliably from transcript shape, or does it need hooks sooner?
- Sprite art source: generated, licensed pack, or DIY?
- Click bubble to focus the terminal: possible from a browser?

## Success Criteria

- `vp dev` shows a live session from an existing transcript within seconds, no config.
- Spawning a subagent shows a visible walk-in and paper handoff.
- Wave+bubble fires on a heuristic attention signal: the final assistant message ends with `?`, or a non-subagent tool call has no result after a timer (R1, R2).
- Holds up with 12 agents on screen.

## Distribution Plan

`npx`-style or clone and `vp dev` locally. No hosting. Decide after spike.

## Next Steps

1. Clone roving-office and one pixel project into scratchpad. Record license, stack, data model, gaps. (1 hr)
2. Decide fork vs scratch. Log decision.
3. Define event interface and transcript tailer (server side, SSE to React).
4. One desk, one agent, typing state. Then subagent walk-in plus paper handoff.
5. Name/gender/project-color generator. Wave+bubble. Coffee break. Leave animation.

## What I noticed about how you think

- You specified the handoff ("handeling paper to one and other") before anything about tech. You picture the interaction, not the architecture.
- "All agents for a certain project shall have similar color": you think in groups of work, not single agents. Fits how people really run many sessions.
- You accepted "study first" instead of building. Good restraint for something at least six people already built.
